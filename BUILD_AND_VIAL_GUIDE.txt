====================================================================
 krsplit P213 (RP2040) 펌웨어 빌드 & Vial 사용 가이드
====================================================================

이 폴더에는 두 가지 빌드가 있습니다.
  - keymaps/default : 순정 QMK용 (VIA/Vial 없음)
  - keymaps/vial     : Vial 앱으로 키맵/매크로를 실시간으로 바꿀 수 있는 버전

RP2040은 플래시(2MB) / EEPROM(wear-leveling, 기본 4KB)이 넉넉해서
V213(atmega32u4)처럼 기능을 줄이는 트레이드오프 없이 그대로 Vial을
켰습니다. 두 버전 모두 실제 컴파일로 검증 완료했습니다.

--------------------------------------------------------------------
1) 순정(default) 버전 빌드 명령어
--------------------------------------------------------------------
git clone --depth 1 https://github.com/qmk/qmk_firmware.git
cd qmk_firmware
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install qmk

mkdir -p keyboards/krsplit/p213/keymaps/default/features
cp <이 폴더>/config.h <이 폴더>/keyboard.json <이 폴더>/p213.c <이 폴더>/krsplit.h <이 폴더>/rules.mk keyboards/krsplit/p213/
cp <이 폴더>/keymaps/default/*.h <이 폴더>/keymaps/default/keymap.c keyboards/krsplit/p213/keymaps/default/
cp <이 폴더>/keymaps/default/features/* keyboards/krsplit/p213/keymaps/default/features/

qmk config user.qmk_home="$(pwd)"
make krsplit/p213:default
# 결과물: krsplit_p213_default.uf2

--------------------------------------------------------------------
2) Vial 버전 빌드 명령어 (반드시 vial-kb/vial-qmk 사용, mainline 아님)
--------------------------------------------------------------------
git clone --depth 1 https://github.com/vial-kb/vial-qmk.git
cd vial-qmk
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install qmk

mkdir -p keyboards/krsplit/p213/keymaps/vial/features
cp <이 폴더>/config.h <이 폴더>/keyboard.json <이 폴더>/p213.c <이 폴더>/krsplit.h <이 폴더>/rules.mk keyboards/krsplit/p213/
cp <이 폴더>/keymaps/vial/*.h <이 폴더>/keymaps/vial/keymap.c <이 폴더>/keymaps/vial/vial.json keyboards/krsplit/p213/keymaps/vial/
cp <이 폴더>/keymaps/vial/features/* keyboards/krsplit/p213/keymaps/vial/features/

qmk config user.qmk_home="$(pwd)"
make krsplit/p213:vial
# 결과물: krsplit_p213_vial.uf2

--------------------------------------------------------------------
3) 플래싱 (RP2040 — QMK Toolbox 필요 없음)
--------------------------------------------------------------------
RP2040은 UF2 부트로더라서 그냥 USB 드라이브처럼 마운트됩니다.
  1. 보드의 리셋 버튼을 두 번 빠르게 누르거나(더블탭),
     BOOT 버튼을 누른 채로 USB를 연결
  2. "RPI-RP2"라는 이름의 드라이브가 컴퓨터에 나타남
  3. krsplit_p213_default.uf2 (또는 _vial.uf2)를 그 드라이브로 끌어다 놓기
  4. 자동으로 재부팅되며 펌웨어 적용 완료
  5. 스플릿 보드이므로 양쪽 다 똑같이 반복 (좌/우 각각 플래시)

--------------------------------------------------------------------
4) Vial 사용법
--------------------------------------------------------------------
- vial.rocks 에서 Vial 앱 다운로드 (Windows/Mac/Linux)
- VIAL_INSECURE = yes 로 설정했기 때문에 언락 콤보 없이 바로 키맵/
  매크로 편집 가능 (분실 시 보안 우려가 있다면 이 옵션을 빼고
  언락 콤보 방식으로 바꿀 수 있음)
- Vial 앱 실행 → 키보드가 자동 인식됨 → Keymap 탭에서 레이어별로
  키 재배치, Macro 탭에서 매크로 작성, Combo/Tap Dance/Key
  Override 도 그대로 사용 가능 (RP2040이라 용량 여유 있어서 다
  켜놨음)
- 나중에 다시 컴파일해서 새 펌웨어를 올려도 Vial로 저장한 키맵은
  보드 자체 EEPROM(플래시)에 남아있음. 완전히 새 UID로 다시
  플래시하면 초기화되니, 편집한 키맵은 가끔 Vial의
  "Export Keymap"으로 백업해두는 걸 추천.

--------------------------------------------------------------------
5) 이번에 발견/수정한 실제 버그 (실제 컴파일로 검증됨)
--------------------------------------------------------------------
1. info.json의 "url": "" 때문에 최신 QMK가 이 키보드 정의 자체를
   조용히 무시함 → url 필드 제거 + 파일명을 keyboard.json으로 변경
   (요즘 QMK는 info.json이 아니라 keyboard.json을 찾음)
2. 각 키에 "matrix":[row,col] 명시가 없어서 "No LAYOUTs defined!"
   에러 → LAYOUT 매크로 본문을 분석해서 90개 키 전부 matrix 좌표
   추가함
3. config.h의 ENCODERS_PAD_A / ENCODERS_PAD_B / _RIGHT (구버전 이름)
   가 최신 QMK의 자동 생성 코드와 충돌해서 "ENCODER_A_PINS redefined"
   컴파일 에러 → ENCODER_A_PINS / ENCODER_B_PINS / _RIGHT (신버전
   이름)로 변경
4. **가장 중요한 버그**: keyboards/krsplit/p213/ 폴더 안의 소스 파일
   이름이 "krsplit.c"였는데, QMK 빌드 시스템은 폴더 이름과 똑같은
   파일명(이 경우 "p213.c")만 자동으로 컴파일에 포함시킴. 그래서
   krsplit.c 안의 코드가 지금까지 한 번도 실제로 빌드에 포함된 적이
   없었음. 이 파일 안에 autocorrection(자동 오타 수정) 기능을
   실제로 동작시키는 process_record_kb() 함수가 들어있어서,
   지금까지 나온 모든 P213 펌웨어에서 자동 오타 수정 기능이 겉으로는
   설정되어 있어도 실제로는 전혀 동작하지 않았을 가능성이 높음.
   krsplit.c → p213.c로 파일명을 바꿔서 해결.
   → V213 폴더도 똑같은 구조(keyboards/krsplit/v213/krsplit.c)라서
     같은 문제가 있을 수 있음. 원하면 V213도 확인해줄 수 있음.
5. p213.c(구 krsplit.c) 안에 다른 키맵 폴더 이름이 하드코딩된
   include 경로(#include "keymaps/default/features/autocorrection.h")
   가 있었음 → keymap.c처럼 "features/autocorrection.h"로 바꿔서
   어떤 키맵 폴더에서도 동작하도록 수정 (4번 버그를 고치고 나서야
   실제로 드러난 문제였음)
6. keymap.c에서 쓰던 KC_MS_BTN1/KC_MS_BTN2, RGB_TOG/RGB_MOD/RGB_HUI/
   RGB_HUD/RGB_VAI/RGB_VAD 키코드가 최신 QMK에서 이름이 바뀌어서
   "undeclared" 컴파일 에러 → MS_BTN1/MS_BTN2, UG_TOGG/UG_NEXT/
   UG_HUEU/UG_HUED/UG_VALU/UG_VALD 로 변경

--------------------------------------------------------------------

--------------------------------------------------------------------
.github/workflows/build.yml 이 push할 때마다 자동으로 default/vial
두 버전을 다 빌드해서 Actions 탭 Artifacts에 올려줍니다.
